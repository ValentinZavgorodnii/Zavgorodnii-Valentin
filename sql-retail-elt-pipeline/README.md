# SQL Retail ELT Pipeline & RFM Segmentation

## О проекте
Данный проект представляет собой полноценный аналитический конвейер (ELT-процесс), развернутый на базе PostgreSQL. Цель проекта — трансформация сырых транзакционных данных e-commerce платформы в готовые продуктовые витрины для бизнес-анализа. 

В коде реализован полный цикл работы инженера-аналитика: от безопасной загрузки `CSV` в staging-слой до расчета сложных когортных метрик, выявления статистических аномалий и оптимизации производительности запросов с помощью индексов.

## Бизнес-вопросы, которые решает проект
Скрипт генерирует витрины, отвечающие на ключевые вопросы продуктовой аналитики:
1. **RFM-сегментация:** Кто наши VIP-клиенты, а кто находится в зоне риска оттока? (Расчет параметров Recency, Frequency, Monetary).
2. **Анализ динамики (MoM Growth):** Как меняется ежемесячная выручка компании по отношению к предыдущему периоду в процентах?
3. **Очистка данных:** Какие заказы являются статистическими выбросами (оптовые закупки или ошибки системы) и как они искажают средний чек?
4. **LTV клиентов:** Сколько реальных денег приносит каждый пользователь с учетом возвратов и отмененных транзакций?

## Архитектура данных (Схема ELT)

Пайплайн разбит на логические слои абстракции, чтобы избежать избыточных вычислений и переиспользовать агрегаты.

### 1. Staging Layer (Сырые данные)
* **Таблица:** `online_retail_raw`
* **Назначение:** Буферная таблица `TEXT`-формата для быстрого и безопасного импорта сырого файла `OnlineRetail.csv` через команду `COPY`. Отсутствие жесткой типизации на этом этапе защищает от падения скрипта при загрузке грязных данных.

### 2. Core Layer (Очищенные данные)
* **Таблица:** `online_retail_core`
* **Назначение:** Центральное хранилище очищенных транзакций.
* **Трансформации:** Приведение типов (`::INTEGER`, `::NUMERIC`), парсинг дат через `TO_TIMESTAMP`, фильтрация пустых `customer_id` и исключение технических артефактов.

### 3. Data Marts (Аналитические витрины)
* **Таблица:** `customer_data_mart`
  * **Назначение:** Агрегированные данные по каждому клиенту (первая/последняя покупка, LTV, количество заказов). Служит базой для быстрой бизнес-сегментации (`VIP`, `Loyal`, `Regular`) без обращения к сырым логам.
* **Таблица:** `rfm_data_mart`
  * **Назначение:** Физическая витрина с расчетом RFM-индексов для маркетингового отдела. Готова к выгрузке и интеграции с BI-системами или Python/Pandas.

## Технический стек и примененные навыки

В скрипте продемонстрировано уверенное владение конструкциями уровня **Junior+ / Middle-**:

* **DDL / DML:** Проектирование архитектуры, `CREATE TABLE AS`, физическое удаление (`DROP TABLE IF EXISTS`).
* **Оконные функции (Window Functions):** 
  * Использование `LAG() OVER` для расчета Month-over-Month (MoM) прироста выручки.
  * Использование `NTILE(5) OVER` для автоматического распределения клиентской базы по квантилям (RFM).
* **Сложные CTE (Common Table Expressions):** Построение многоступенчатых виртуальных конвейеров через оператор `WITH`.
* **Продвинутая математика:** Поиск аномальных заказов (Outliers) с использованием правила 3-х сигм (`STDDEV`, `AVG`, `ABS`).
* **Оптимизация производительности (Performance Tuning):**
  * Анализ планов выполнения через `EXPLAIN ANALYZE`.
  * Переход от `Sequential Scan` к `Index Scan` благодаря созданию `B-Tree` индекса на ключевое поле фильтрации и джойнов.
* **Экспорт результатов:** Сохранение финальной витрины обратно в `.csv` для дальнейшего машинного обучения.
